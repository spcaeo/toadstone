The check reference

For the complete documentation index, see llms.txt. Every page here is also served as Markdown at the same address with .md instead of .html.

Every check Toadstone can report, with its slug, its severity and what to do about it. This file is generated from a running install's own catalogue (tools/generate_checks_doc.py), so it cannot drift from the wording the code actually uses.

The slug is the stable part. It is what the API filters on, what a finding carries in its check field, and what /checks#<slug> links to in the running app. Names and wording may be improved; slugs are not renamed without a reason.

180 of these have been observed firing in a real crawl of the deliberately broken fixture site in tests/coverage_site.py, across its several modes. Those are marked ✅. A check with no mark is not a check that does not work - it is one this fixture has no page for yet, and that is a gap in the fixture, recorded rather than hidden.
